# 03 · 实现

## 进程与边界

引擎（mineflayer）跑在**子进程**里，主进程通过 IPC 指挥。这条边界同时解决四件事：

1. **事件循环争用**：物理 tick 20 Hz，每个 tick 都在解析包、更新世界状态；主进程还要跑 Cordis、模型调用、UI。
2. **崩溃隔离**：mineflayer 生态有已知的卡死与未捕获异常模式，子进程死掉主进程还在，换新代次重连。
3. **重连换代**：bot 实例重连后会换一个新对象，所有令牌（租约、意图、TTL、监听器）都必须带 `connectionGeneration`，旧代一律作废。**不做这条，旧代次的意图会在新 bot 上执行。**
4. **运行时选择自由**：主进程用 Bun，引擎子进程可以用 Node。

IPC 分三类就够，不用加协议：要回执的请求、单向投递、子进程反问宿主；日志、事件、状态都是单向。现在用到两条：父侧发 `stop` 与 `req`（要回执的原语），引擎推 `view`（一帧世界）、`note`（连接、进世界、断线、出错）与 `rep`（原语的回执）。「子进程反问宿主」还没用上。

引擎默认跑 **node**，主进程留在 Bun 上。实测 mineflayer 4.39 在两边都能加载并连上，`runtime` 因此是个开关而不是硬约束。

## 脊髓层的进程内结构

```
tick 边界钩子  →  采样器目录  →  快照（带 observedAt 与代次）
                                    │
                     窗口内所有弧共享这一份快照
                                    │
                              按路径投影 + 渲染
                                    │
                   签名没变？→ 复用上次结果，不问
                     变了？→ 单飞发请求（同时只一个在飞）
                                    │
                    结果落缓存：{选择, 概率, 置信, at, ttl, 模型版本}
                                    │
                    传出层每帧读缓存；过期就退回保守行为
```

四个必须写对的点：

- **一个窗口采样一次，窗口内共享。** 否则 `hp` 和位置来自不同 tick，判据建立在自相矛盾的世界模型上。
- **快照不可变、带 `observedAt` 与代次。** 这一条换来离线回放：把录制的快照序列喂给渲染器，不动游戏也能重跑判据。
- **单飞。** 同一时刻只允许一个请求在飞，否则慢的那次回来会覆盖新结果。
- **结果带 TTL。** 抖动是 1.6 倍（252 → 402 ms），不设 TTL 等于让过期判断继续开车。
- **状态没变就续期。** 投影结果一致说明世界没动，判断仍然成立，于是把存活期往前推而不是重问。心跳停了续期也停，判决自然过期。所有时刻都取宿主的心跳时钟（`pulse` / `directive` 的 `now`），不是墙钟；模型延迟另记在 `ms` 里。

## 判断模型的客户端

- **钉住版本号**，不用浮动别名。要回放回归，就必须记死 `jev-1.13.0`。
- **按签名缓存**：状态签名没变就不发请求。`windowMs` 是上限而不是负载。
- **算清最坏代价**：几百 token 的战斗态、3 Hz 满速，约 3.6 Mtok/小时，是每小时几毛钱量级；换成每 tick 灌全量状态会贵一百倍，还会正好吃满请求配额。所以"上限 + 签名缓存"不是优化，是设计前提。
- **state 要小**：每个弧只投它投影出来的那几个字段。
- 契约按 [TypeSafe 评估端点](https://docs.typesafe.ai/api) 实现：`POST`，`Authorization: Bearer <API_KEY>`，体为 `{ state, model, questions }`；`questions` 按问题 id 建表，id 本身不进问题对象。响应按三种回答的联合类型校验，并逐条核对"回答的 type 与问题的 type 一致、每个问题都有回答"，对不上就当作判断失败，不落缓存。
- 问题有三种：`noul`（是否，回概率）、`choice`（选一个，回选项与分布）、`score`（沿档位打分）。`choice` 与 `score` 带 `confidence`，**`noul` 不带**，本层按概率离抛硬币多远折算（`|2p−1|`）后再进同一个置信门；一条弧的整体置信取最弱的那条回答。

## 传出层：原语与终止判据

传出层是纯代码（D-01），它不判断，只把判决变成动作。第一批四个原语：

| 原语     | 参数       | 终止判据                                          | 默认超时 |
| -------- | ---------- | ------------------------------------------------- | -------- |
| `walk`   | `to`       | 到目标的水平距离 ≤ 0.8（状态，单调可达）          | 5 s      |
| `jump`   | —          | `onGround` 变 false 且 y 上升（状态）             | 1.5 s    |
| `dig`    | `at`       | `dig()` 落地——mineflayer 只在方块变成空气时才落地 | 10 s     |
| `attack` | `entityId` | 目标受伤 / 死亡 / 从世界消失（事件沿）            | 3 s      |

纪律：

- **下达不阻塞。** 原语是背景状态，不是一次调用：`order()` 立刻返回句柄，结果由主循环来读（`outcome()`）。这和脊髓层"后台预取、主循环读上次结果"是同一个形状；传出的这一侧不该留一个把人吊住的 promise——动作在跑这件事必须是**看得见**的，否则新判决到了也没人知道该不该打断它。
- **判据读世界事实，不数帧。** 帧数在丢包、卡顿、服务器 tick 抖动下毫无意义；判据是"这条动作做成了没有"，不是"发了几次包"。
- **事件类判据挂在沿上，不比两个时刻的快照。** "目标血量比出手时低"会被回血击穿，"此刻这块方块是空气"会被补块击穿——两桩都是真做成了却判成失败。**凡判据形如"现在比出手时更好或更少"，先问它是状态还是事件。**
- **沿必须由引擎求值。** 父进程每 `pushMs` 才采一帧，两次采样之间的事件会被整个漏掉；沿无法从采样里重建，所以判据归离事件源最近的那一侧。
- **超时是最后一道闸，不是判据。** 判据看不到进展才轮到它收手。失败的回执必须把现场带出来（"水平差还有 3.00""目标一直没受伤"），一句干巴巴的"失败"等于把排障成本推给下一个读到它的人。
- **收尾必松手。** 控制状态是外部可见的世界副作用：`walk` / `jump` 无论成没成都松开，留着 `forward` 就是让 bot 一直撞墙。原语串行，排队贴着 bot 放在引擎一侧，父侧看到的只是一个还没回执的请求。

**回执带执行时的连接代次。** 父侧拿它跟发出时比：对不上就作废（`回执作废：执行时是第 2 代，发出时是第 1 代`）。和第 3 条（换代令牌要贯穿）是同一件事在下行方向上的落实——旧代次动作的结果被当成新代次的事实，比不执行更糟。

原语是**代码**，不在可编程范围内（D-04）；编排层能改的是弧（用哪几个动作、什么条件），不是动作怎么实现。

## 三类工件放哪

| 工件   | 形态                       | 位置                        | 谁写     |
| ------ | -------------------------- | --------------------------- | -------- |
| 弧库   | JSON，版本号递增，旧版保留 | 包内默认 + 运行时覆盖文件   | 模型与人 |
| 动作库 | TypeScript                 | 仓库内，`pending/` 为草案区 | 人为主   |
| 账本   | JSONL 追加                 | 数据目录                    | 程序     |

弧库要两层：默认随仓库走，覆盖能就地改；配置目录丢了不影响运行。

账本一行一次判断：

```json
{
  "arc": "kite",
  "model": "jev-1.13.0",
  "sig": "6a1f0c4d",
  "state": { "hp_percent": 45, "enemies[*].dist": [6] },
  "answers": { "horiz": { "type": "choice", "choice": "Away", "probabilities": { "Away": 0.88, "Near": 0.12 }, "confidence": 0.81 } },
  "confidence": 0.81,
  "at": 1200,
  "seenAt": 1200,
  "generation": 2,
  "ttlMs": 1500,
  "ms": 287,
  "usage": { "input_tokens": 318, "output_tokens": 34 }
}
```

`model` 记的是服务方回的实际版本，不是请求里写的别名。有 `state` 和 `sig`，任何一条判断都能还原成"它当时看到什么、答了什么"，也能看出哪几次是同一个状态。

## 动作库的创作闭环

动作是可执行代码，所以模型不能直接往库里写：

```
模型写草案 → pending/ 目录
   → 子进程加载（带超时，失败即丢弃）
   → 用录制的回放跑这条动作的判据
   → 通过 → 提升进正式库（带版本号）
   → 不通过 → 回执把失败现场交回去
```

这条闭环依赖前面两样东西：子进程边界，和可回放的快照。缺一个，模型写动作就是盲写。

**不做沙箱**：给动作的上下文只暴露世界操作方法，加载在子进程里跑、超时就杀，提升需要人工或规则放行。

## 事件面

- 任务终态与反射汇报：**立即投递**；急报不受节流。
- 世界变化摘要：窗口节流（时间窗 + 位移阈值），同内容不重发。
- 快照：按固定秒数投递，与上一份相同则不产生事件。
- 立即投递前**先结一次摘要**，否则"做完了"会排在它自己那批采集前面，时间轴是倒的。
- 反馈有预算：超了静默跳过，不补一句"我本来还想提醒"。

观测面最便宜的做法是一个本机 HTTP 页面，每秒自拉一次判断日志：时刻、弧、选择、置信、分布、理由、耗时、现场。纯读，写起来几十行。

## 四个陷阱

1. **别在事件回调里同步等模型**：物理 tick 20 Hz，同步等就是丢包。异步预取、主循环读上次结果。
2. **别每次渲染都重新解析弧**：加载时校验并编译成内部结构，渲染只做取值与拼装。
3. **换代令牌要贯穿**：租约、意图、TTL、监听器全部带代次。
4. **运行时已经验过**：mineflayer 4.39 在 Node 与 Bun 下都能加载、也能真连上世界（本仓库的集成测试跑在 Bun 里，用 `bun src/engine.ts` 起引擎子进程）。生产默认仍是 Node，主进程留在 Bun；这个选择被进程边界局部化，随时可翻。

## 里程碑

1. **引擎能跑**：子进程连上服务器，采样目录与快照能出正确读数，原语能执行。不含任何模型。
2. **一条弧**：硬编码的弧 + 判断模型接上，做"看到敌对就选打 / 退 / 观察"，同时做随机对照。
3. **数据化**：弧落成数据文件，渲染器按路径投影，决策账本落盘，回放能跑通。
4. **编排**：编排层读账本改弧，先人工确认，再逐步放开；回放回归进 CI。
5. **动作库闭环**：pending 流程跑通，模型能加动作草案。
