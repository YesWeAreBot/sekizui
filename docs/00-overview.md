# 00 · 定位与分层

## 一句话

让慢模型为合适的阶段编写反射弧，让快模型在运行时选择语义意图，代码把意图落地成具体动作，预设动作库是两者之间的共享资产。

三个角色：慢模型是作者，快模型是脊髓，动作库是词汇表。

## 这个仓库做什么

本仓库只做**脊髓层**。

- 上层编排（当前目标、什么时候换一套弧、每条弧的判据怎么写）由慢模型和人通过工具面完成。
- 下层传出（按键、瞄准、时序）与采样（世界状态从哪来）由 nerve 一侧完成。
- 本层负责中间那一段：把编排层写下的弧，变成传出层每几百毫秒读一次的判断。

## 三个时间尺度

不是三种智能的排序，是**三种消费速率**的排序。谁快谁慢由"产物被谁以多快消费"决定，不由模型强弱决定。

| 层         | 周期       | 产物                                         | 被谁消费 | 失效的后果         |
| ---------- | ---------- | -------------------------------------------- | -------- | ------------------ |
| 传出层(腱) | 16–50 ms   | 按键、点击、瞄准、时序                       | 游戏进程 | 手感变差，动作落空 |
| 脊髓层     | 100–500 ms | 语义判断：触发与否、选哪条、往哪个方向变化、什么档 | 意图落地层 | 判据过期，做错决定 |
| 编排层     | 秒–分钟    | 弧的增删改、动作库草案                       | 脊髓层   | 阶段错配，目标漂移 |

模型只在后两层出现。**能在哪一层出现，由产出的消费速率决定**：编排层的产物要活几十秒到几分钟，所以它慢得起；脊髓层的产物几百毫秒就被消费一次，所以它必须快。

由此推出一条实现前提：**脊髓层的节律远快于编排层，但不要求等于帧率。** 传出层是帧级的，脊髓层几百毫秒一次即可，前提是异步预取：后台按窗口周期发问，主循环读上一次的结果，永不同步等。

## 脊髓层的两半

生物学上脊髓不只是弧的连线，还有门控、局部仲裁、调制。所以这一层内部再分两半：

- **弧**（先天部分）：条件触发、动作直连、不经模型。保命底线，阈值归操作员，模型不许改。
- **门控 / 仲裁 / 调制**（需要模型的部分）：该不该触发、多路同时成立时选哪条、距离或高度应如何变化、这个场合算不算危险。这些判据是语义的，写不成代码。模型输出的是有限语义意图，不是坐标、实体任意 ID 或按键时序。

两半的边界规则：**凡能用探针精确判定的（方块在不在、血多少、包够不够），永远留在代码；凡是现在靠魔数压着的语义规则，才是模型该接管的。**

## 三份薄接口

本层与外部的全部边界：

| 接口     | 谁实现           | 干什么                                             |
| -------- | ---------------- | -------------------------------------------------- |
| 采样面   | nerve 一侧       | 取一份带连接代次的世界快照（Minecraft 一侧已落地） |
| 意图汇   | nerve 一侧       | 把判断交给传出层执行（Minecraft 一侧的原语已落地） |
| 决策账本 | 本层写，编排层读 | 还原"它当时看到什么、答了什么"                     |

## 意图与手段

脊髓层不直接填写连续控制参数。它消费当前目标的压缩上下文，输出 `choice`、`noul`、`score` 等有限判断；代码再把判断落地成当前世界里的目标、参数和时序。

```text
前台慢模型：目标、阶段、完成条件、约束
        ↓
脊髓层：投影状态 + 语义判断
        ↓
意图落地：目标解析、参数求值、几何计算、手段选择
        ↓
传出原语：移动、跳跃、挖掘、攻击、瞄准、时序
```

能由代码确定的目标和参数由代码确定；只有有限候选中的语义取舍交给快模型；开放式目标仍归前台慢模型。

## 摊开的两个库

这是最容易混淆的一处区分：

- **动作库**：可执行的预设动作。对模型暴露语义动作，内部由原语（走一格、跳、放置、攻击、挖、合成）组合成行为，再形成流程（某 boss 的手册）。它是代码。
- **弧库**：弧实例本身，即下面 `01-reflex-arc.md` 里那四个字段。它是数据。

弧引用动作的 id，不复制实现。编排层的产物落在弧库；动作库通常由人写、由慢模型投草案。

## 与宿主的关系

按 Athena 的分法，这是一条**挂在 World cortex 上的可选认知路径**，不是新的核心架构（见 `02-prior-art.md` 第三节）。它替换掉的是 `Continuous / World` 形态里"每拍一次 tool-call"那一步，而不是那整个 Cortex。

Cordis 只用来做装配与生命周期：本层是一个 Service，装配方式与生态里其他 Service 相同。
