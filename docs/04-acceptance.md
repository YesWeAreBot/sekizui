# 04 · 验收

这套设计要立的功必须能被证伪。判据一句话：**去掉模型，结果得变差。**

## 四条

1. **随机种子，不预置坐标与脚本。** 声明精度是"N 个随机种子下的成功率"，不是"通关"。遇到卡住读日志定位结构性问题，不给某个种子打补丁。

2. **分档消融，而且必须拆开测。**

   | 关掉什么                       | 测的是什么                           |
   | ------------------------------ | ------------------------------------ |
   | 编排层写的弧（退回人写的弧）   | **编排质量**：模型写的弧值不值       |
   | 脊髓层（退回规则或同分布随机） | **判断质量**：模型的判断值不值       |
   | 动作库的某个子集               | **库的覆盖**：失败是不是因为选项没给 |

   三档混测，两个变量互相掩盖，结论说明不了任何事。现有实现里已有可照搬的开关形态：关知识、换随机大脑、同分布对照、无 key 落 baseline。

3. **每次判断可还原。** 输入 state 摘要 + 输出 + 模型版本，并且能回放。措辞上只写读数与概率，不写成"这里危险、建议拉开"——基础设施只陈述可确认的事实。

4. **指标。** 编排层的调用频率随运行时长下降（复用生效）；脊髓层的置信分布上移；成功率上升。若模型每分钟都要说话，说明弧没编成。

## 三条成立前提

这套设计能跑，依赖三件事，缺一条就要先补：

1. **脊髓层的节律远快于编排层，但不要求等于帧率。** 异步预取，永不同步等。
2. **每个阶段的候选动作集有限且已知。** 候选集漏项不会有任何报错信号——它只会在缺项集合里挑一个还行的。所以候选集必须带保底动作，候选集版本必须进日志，事后才能判定"这次失败是不是因为选项没给"。
3. **失败必须交出现场。** 没有可读的失败现场，编排层改弧就是盲改，闭环立刻断。

## 回放回归是前置条件

判据写错不会报错，只会安静地做错决定，这比动作代码写错更难发现。所以：

- 机械可判的判据必须是纯函数，能在录制的快照序列上重跑。
- 改一版弧或判据，先在回放上跑新旧两版，比对选择分布与结果，过了再上。
- 弧版本 × 动作库版本 × 模型版本三样一起记，否则回归没有基准。

## 不做

- 不拿一次直播或一次录像当证据。
- 不拿"跑通了"当验收。声明到哪一层，就报哪一层的数字：模型写的 bot、模型在环、还是人在环。
