## 被推翻或被纠正的

| 编号 | 曾经的方案                           | 推到什么程度                                                 | 依据                                                                            |
| ---- | ------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| R-01 | 每 tick 把上下文交给快模型           | 改为窗口周期的上限 + 异步预取；帧级只留纯代码                | 实测 300 ms 与 50 ms 帧长的差距；"让 250 ms 的判断直接当按键会吃满伤害，我测过" |
| R-02 | 对话域对反射弧的否决（四条理由）     | 在游戏域三条失效，只有"第二个决策主体的复杂度"仍成立并已量化 | `02-prior-art.md` 第三节                                                        |
| R-03 | "快模型是仲裁器，不是反射弧"         | 命名之争。生物学上脊髓本就含门控、仲裁、调制，两者不冲突     | 接受"快模型做脊髓层"                                                            |
| R-04 | 把"全部状态变量"理解为全量灌进 state | 用户指的是**可见清单**。清单对，载荷错                       | `01-reflex-arc.md` §状态投影                                                    |
| R-05 | 一开始就抽跨游戏的通用脊髓层包       | 只有一个目标平台，先不抽象；第二个平台出现时再抽，且是机械的 | 不为当下的需要之外的抽象付费                                                    |
