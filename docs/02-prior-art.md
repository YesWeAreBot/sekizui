# 02 · 先例对照

三份参考各自已经实现或否决了这套分层的一部分。以下事实均来自只读源码与文档，未运行过它们。

## 一、TerraBlind：已有传出层与脊髓层，缺编排层

- 仓库：`Reisenbug/TerraBlind`（本地 `../.tmp/TerraBlind`），C# / tModLoader 的泰拉瑞亚 bot。
- **脊髓层**：Jev 每 ~300 ms 答一次（实测中位 300、最小 252、p90 402）。同一份 state 一次问完所有问题。
- **传出层**：反射层每帧（60 Hz）翻译成按键——瞄准、距离、双击冲刺时序、钩爪落点、跳跃的“松一帧”、意图过期回退，全归代码。
- **意图与手段分开**：Jev 只说要达成什么（`Horiz` / `Vert` 两轴），跳 / 二段跳 / 翅膀 / 钩爪选哪个由代码算。它不填写坐标、实体任意 ID、瞄准点或连续按键参数。
- **目标和瞄准也归代码**：`Combat.Tick()` 由代码选择目标和武器，`Lead()` 计算提前量，`Cursor.AimPx()` 每帧瞄准；Jev 不是瞄准器。
- **背板即一段中文文字**（`Jev/Fight/BossBook.cs`），不是分支；加一个 boss 通常只是加一条文字。背板能在游戏内逐条改、逐条 on/off。
- **对照组齐备**：`RandomBrain` 把 Jev 换成随机选择器；`BossKnowledge` 关掉全部背板；`JevPrior` 按 Jev 的实际分布抽样作为同分布对照（"比例和 Jev 一样，差的只剩什么时候选"）；没有 key 时战斗层退回保守 baseline。
- **它自己写下的关键一条**：`Dodge.cs` 开头 —— "让大约 250 ms 的判断直接当按键会吃满伤害。对，我测过。"

**缺的**：boss 手册是人手写的，没有自动生成与迭代的闭环。这就是本仓库要补的那一块。

TerraBlind 对本仓库的直接启发是：JEV 应作为有限语义意图的选择器，动作库内部再把意图落地成目标、参数和原语。它证明了“语义判断 + 代码执行”这条桥，不证明后台模型已经能自动学习或安全部署新动作。

## 二、Cortico：已有传出层、动作库与编排层，缺脊髓层

- 仓库：`Pal-AI-Lab/Cortico`（本地 `../references/Cortico`），TypeScript + mineflayer 的通用 bot 框架。
- **先天反射**：受击反击、防溺水上浮、挨烧逃离、深坠、低血脱离；200 ms 心跳；**全部不经 LLM**；事后以事件汇报；阈值与开关集中在配置里并热改即生效；抢占走 `preempt()`。
- **维持层与反射层的分界**写得很准：**"要不要放下手上这件事"** —— 反射（岩浆、低血、溺水）打断并接管，维持（补光、垫脚、补料）不打断，补一格、插一根，回到原来那一步。
- **仲裁用声明的数值，不用模型**：`body-lease.ts` 让各类 owner 提交同一份短租约——生存收益、紧迫性、可行性、进展、连续性、执行风险、中断成本；"仲裁器不认识具体怪物或动作名"；优先级 `ENV > FIGHT > TASK`。
- **写入面是固定旋钮**：`mc_policy` 六格（垫脚料名单、火把名单、照明时机、赶路偏好、不收着的物品、战斗风格），五格落盘，`fight` 不跨重启且回弹时强制播报。自保阈值明确归操作员，`mc_policy` 不提供。
- **判定分机械与主观两类**：目标计划每一步有 `verify`（探针闭集：block / inventory / blueprint / position / entity / item / status）与 `judgment`；且"全部步骤已登记，仍要现读机械旁证后才能 done"。
- **措辞纪律（PWSR 主客观纪律）**："「路径进入了你标记的危险区」可以，「系统判断这里危险」不可以。"基础设施只陈述可确认的事实。

**缺的**：没有脊髓层。所有语义判断要么写死成魔数（战斗层里成堆：8 格内贴身侧移、苦力怕贴脸后撤、5 分钟战斗占比超限进冷却），要么推给秒级的 agent。

## 三、Athena：已经把"反射弧"否决过一次，并写下了重新引入的条件

`athena-harness/docs/cookbook/02-multi-scene-attention.md` 有一节「否决方案：反射弧」，定义与本项目一致：

> 反射弧是主心智之外的第二条认知路径——独立于主心智并行运行，使用轻量模型和有限上下文，对非 focus 场景的事件做低级别判断和有限行动。

当时否决的四条理由，对到游戏域：

| 否决理由                        | 在对话域                     | 在游戏域                                         |
| ------------------------------- | ---------------------------- | ------------------------------------------------ |
| 减少响应延迟不是产品目标        | 成立                         | **反转**。20 tick/s，延迟就是产品本身            |
| 主心智已有能力处理非 focus 事件 | 成立（step delta、旁路读取） | **不成立**。主心智是秒级，跟不上 50 ms 的事件流  |
| 第二个决策主体的复杂度不值得    | 成立（边界不清、收益不明）   | **收益可测**（随机种子下的成功率），且边界已划清 |
| 灰色地带归为"不回复"            | 成立                         | **不成立**。不回复等于不动作，等于死或卡死       |

那一节还写了重新引入的条件，游戏域命中其中两条："某些场景要求无条件的低延迟确认"、"事件量远超主心智处理带宽，且不回复不可接受"；并预告了引入形态——**"届时反射弧可作为 Cortex 的可选扩展能力引入，而不是从第一天就作为核心架构的一部分"**，以及 `nerve-minecraft` 作为平级 Nerve 的路线。

本项目的定位正是这一条：挂在 World cortex 上的可选认知路径。

## 四、这类 demo 为什么会烂掉

判据只有一句话：**去掉模型也照样通关。**

分两种烂法，要分开治：

1. **固定种子 + 固定脚本**。治法是随机种子、不预置坐标、分档消融。见 `04-acceptance.md`。
2. **把模型放在每一步**（1–5 秒一步）。那不是"决策快"，是慢到没法玩。真正的分层是把模型放在它值钱的尺度上。

另外提醒一处声明纪律：如果模型是离线产码，就宣称"模型写了一个 bot"，别宣称"模型在玩"。两者都没问题，混着说才是被打假的对象。
