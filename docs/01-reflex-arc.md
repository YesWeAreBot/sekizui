# 01 · 反射弧

## 四件套

一条弧实例就是四个字段，这四件就是"可编程"的全部内容：

1. **触发条件**（`on`）：什么时候这条弧可被激活。机械部分用探针读世界事实，语义部分交脊髓层判断。
2. **候选动作子集**（`liveActions`）：激活时，哪些预设动作进入这次决策的清单。取自动作库，必须包含一个保底动作（`fallbackAction`）。
3. **判据与意图**（`questions`）：脊髓层在这批语义动作或意图里按什么选。每条问题一个 `id`、一段 `instructions`、一组 `criteria`。问题输出有限选择，不负责填写坐标、实体任意 ID、瞄准点或按键时序。
4. **退出条件**（`off`）：什么时候失效。**必填。**

第 4 件最容易漏。只写"何时生效"不写"何时失效"，留下的是僵尸弧：一条再也无法失效的弧会一直压在决策清单上。守卫补上剩下的部分：`ttlMs`（判决最长存活多久）与 `minConfidence`（低于它退回保底动作）。

```
ArcSpec {
  id, on, off,
  projection:    [路径…],              // 状态投影，只放这一步真正要用的字段
  questions:     [{ id, instructions, criteria }…],
  liveActions:   [语义动作 id…],       // 取自动作库；具体参数由代码落地
  fallbackAction: 动作 id,             // 必须在 liveActions 里
  guards:        { ttlMs, minConfidence }
}
```

## 三类弧

| 类型   | 触发      | 判据       | 例子                                   |
| ------ | --------- | ---------- | -------------------------------------- |
| 先天弧 | 代码      | 代码       | 岩浆逃生、溺水浮头、深坠、低血脱离     |
| 混合弧 | 代码      | 模型参数化 | 补光：触发是代码，去哪补、值不值是模型 |
| 后天弧 | 模型 / 人 | 模型       | boss 走位、威胁取舍、路线偏好          |

**安全不动点**：先天弧的阈值、动作库的实现、动作库的准入，这三样不在可编程范围内。编排层能改的是弧，不是命。

## 状态投影与变量目录

编排层能看到一份**变量清单**（`SampleCatalog`）：采样面能提供哪些变量，各自的类型、单位、何时有效、大约多少 token。这份清单归代码所有，慢模型只读。

但每次调用送给模型的 `state` **不是全量**，而是弧声明的投影结果。两条理由：

- 判断质量：无关细节是干扰项，state 越大越容易读偏。
- 成本与延迟：state 的大小直接乘在调用次数上。

投影按路径求值，字段名就是路径本身（`enemies[*].dist`），判断日志据此能直接还原现场：

```
读数：敌人 3 个，最近 6 格，生命 45%
判断（jev-1.13.0，0.72）：horizontal=Away，vertical=Level
state 摘要：{"hp_percent":45,"enemies[*].dist":[6,9,14]}
```

引用了目录外的变量在加载弧时当场报错，不等到渲染时冒出一个 `undefined`。投影路径在加载时解析成路径段，渲染时不再碰字符串。

## 写入面与两个作者

弧库由人和慢模型共写。这能成立的前提只有一条：**工件必须是结构化数据加代码，不能是自由文本**。人和模型都要能改，就必须能校验、能 diff、能回滚、能回放。

| 谁   | 能改                                         | 不能改     |
| ---- | -------------------------------------------- | ---------- |
| 人   | 动作库实现、先天弧、保命阈值、动作库准入     | —          |
| 模型 | 弧实例（四件套）、语义动作选择与判据、动作库草案 | 保命阈值与低层执行参数 |
| 双方 | 弧的取舍与命名                               | 安全不动点 |

两条纪律：

- **一份真相**：同一个语义不要有两处判据。名单、阈值、开关各只有一个出处。
- **版本三元组**：弧版本 × 动作库版本 × 模型版本，三样一起记。模型别名会漂，不记死版本号，回归分析就没有基准。

## 模型输出边界

JEV 是语义意图选择器，不是连续控制器。默认顺序：

1. 代码确定目标和参数；
2. 快模型在有限候选中做语义取舍；
3. 前台慢模型决定开放式目标与长期阶段；
4. 低层原语负责几何、瞄准、按键时序和完成判据。

例如，`retreat_from_threat` 可以由代码选择威胁实体、计算退路并调用 `walk` / `jump`；模型不填写 `entityId`、`to` 或帧数。只有在目标选择本身需要语义判断时，才把当前有限候选做成 `choice`。

弧的 state 可以带当前目标的最小上下文（目标、阶段、完成条件和约束），否则快模型只能做脱离长期任务的通用判断。

## 闭环

```
脊髓层产出  →  判断记录（state 摘要、选中项、概率、置信、延迟、模型版本）
                  ↓
编排层输入  ←  判断记录 + 世界状态快照 + 失败现场（无进展 / 卡死 / 死亡）
                  ↓
编排层输出  →  弧的增删改 + 动作库草案
                  ↓
人          →  审 diff、审失败样本、批动作库草案
```

信号优先级：**低置信样本 > 反复失败 > 常规记录**。低于 `minConfidence` 被退回保底动作的那些样本，就是"判据没覆盖到这种情况"的直接证据，也是给编排层最干净的输入。

评价这套闭环是否做成，看一个指标：**编排层的调用频率随运行时长下降，成功率上升。** 模型把弧写对了，运行时就不需要它；如果它每分钟都要说话，说明弧没编成。

## 反馈纪律

反馈本身要有预算，否则它会变成新的噪声源：

- 定时触发走节流窗口；事件驱动走急报（急报不受节流）。
- 同一内容不重发（快照与上一份相同就不产生事件）。
- 同一问题一轮只答一次。
- 预算用完静默跳过。**不补一句"我本来还想提醒"**——那本身又是一条提醒。
