# @sekizui/nerve-minecraft

Minecraft 世界一侧。上行实现 `@sekizui/arc` 的**采样面**，把 bot 看到的世界交出去；下行实现**传出层**，把原语做实。

## 为什么引擎在子进程里

mineflayer 的物理 tick 是 20 Hz，每个 tick 都在解析包、更新世界状态；主进程还要跑 Cordis、模型调用、UI。放一起就是互相拖。把引擎隔到子进程还顺带解决三件事：崩溃隔离、重连换代、运行时选择自由（主进程用 Bun，引擎用 Node）。

```
父进程(Bun)                          引擎子进程(Node，默认)
  NerveMinecraft                        mineflayer bot
    ├─ spawn ───────────────────────→      ├─ 每 pushMs 推一帧 view
    ├─ child.on("message") ←───────────────┤  note：连接、进世界、断线、出错
    ├─ sampler.read()  ← 最新一帧           └─ rep：原语的回执
    ├─ order(原语) ──────────────────→   执行原语，判据读世界事实
    └─ stop() ──────────────────────→   bot.quit() 后退出
```

## 用法

```ts
import { NerveMinecraft } from "@sekizui/nerve-minecraft";

const nerve = new NerveMinecraft({ host: "127.0.0.1", port: 25565, username: "sekizui" });
nerve.start();
spinal.useSampler(nerve.sampler); // 上行：交给脊髓层

const order = nerve.order({ op: "attack", entityId: 1001 }); // 下行：下达，立刻返回
order.running(); // 还在跑吗
order.outcome(); // 跑完了没有；出了结果就是 PrimitiveOutcome
```

| 选项          | 默认              | 说明                     |
| ------------- | ----------------- | ------------------------ |
| `host`        | —                 | 服务器地址               |
| `username`    | —                 | 离线身份名               |
| `port`        | `25565`           | 端口                     |
| `version`     | mineflayer 的默认 | 协议版本                 |
| `auth`        | `offline`         | `offline` 或 `microsoft` |
| `pushMs`      | `100`             | 多久推一帧世界           |
| `reconnectMs` | `5000`            | 断线后隔多久重连         |
| `runtime`     | `node`            | 引擎子进程的运行时       |
| `enginePath`  | `lib/engine.js`   | 引擎入口                 |

## 读不到就读不到

采样面不编造默认值。bot 还没进世界、连接断了、还没收到血量，`read()` 就**抛错**——脊髓层会把这一拍当作没有可用读数，旧判决停止续期，过了存活期自然退保底。`generation()` 只在真的进过世界之后才往后走。

## 变量目录

三十八条，分六个根变量与它们的叶子：

| 根               | 内容                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------ |
| `bot`            | 血量、血量百分比、饱食度、维度、一天中的时刻、坐标、朝向、是否着地                   |
| `entities`       | 附近的实体：id、名字、类型、分类、是否敌对、距离、高度差、血量、坐标。玩家与自己除外 |
| `entities_total` | 实体的**总数**（列表只推最近的十六条，截断不瞒着）                                   |
| `players`        | 附近玩家与距离                                                                       |
| `inventory`      | 背包：物品名、数量、槽位                                                             |
| `holding`        | 手上拿着的东西                                                                       |

**不按类型预筛。** mineflayer 的 `entity.type` 是 `hostile` / `animal` / `projectile` / `object` 这一层分类，僵尸是 `hostile` 而不是 `mob`；"值不值得管"是语义判断，留给弧，代码只把分类原样交出去。

`hostile` 由代码按 minecraft-data 的分类判定（`Hostile mobs`），不交给模型猜。距离、血量百分比、高度差也都是算好的——模型读现成的数就行。

实体行里带 `id`，因为传出层的原语要按 id 指到具体的那个实体（弧答"攻击最近的敌对"，`entities[*].id` 就是它的落点）。

## 传出层：原语与终止判据

`order(primitive)` 把原语发进子进程，**立刻**返回一个句柄。四个原语：

| 原语     | 参数       | 终止判据                                          | 默认超时 |
| -------- | ---------- | ------------------------------------------------- | -------- |
| `walk`   | `to`       | 到目标的水平距离 ≤ 0.8（状态，单调可达）          | 5 s      |
| `jump`   | —          | `onGround` 变 false 且 y 上升（状态）             | 1.5 s    |
| `dig`    | `at`       | `dig()` 落地——mineflayer 只在方块变成空气时才落地 | 10 s     |
| `attack` | `entityId` | 目标受伤 / 死亡 / 从世界消失（事件沿）            | 3 s      |

**下达不阻塞。** 原语是背景状态，不是一次调用：`order()` 不等它跑完，结果由主循环来读（`order.outcome()`、`nerve.orders()`）——和脊髓层"后台预取、主循环读上次结果"同一个形状。要等的地方自己等（轮询 `outcome()`），传出的这一侧不留一个把人吊住的 promise。

纪律：

- **判据读世界事实，不数帧。** 帧数在丢包与卡顿时毫无意义，"到了没有""方块还在不在"永远为真。
- **事件类判据挂在沿上，不比两个时刻的快照。** "目标血量比出手时低"会被回血击穿，"此刻这块方块是空气"会被补块击穿——两桩都是真做成了却被判成失败。`attack` 因此挂 `entityHurt` / `entityDead` / `entityGone`，`dig` 直接以 `dig()` 的落地为准。
- **沿必须由引擎求值。** 父进程每 `pushMs` 才采一帧，两次采样之间的事件会被整个漏掉；沿无法从采样里重建，所以判据归离事件源最近的那一侧。
- **超时是最后一道闸，不是判据。** 判据看不到进展才轮到它收手；失败时回执把现场带出来（"水平差还有 3.00"），不交一句干巴巴的"失败"。
- **收尾必松手。** `walk` / `jump` 无论走到没走到都松开控制状态，留着 `forward` 就是让 bot 一直撞墙。原语串行，同一个 bot 上并发控制会互相打架。

回执带**执行时的连接代次**。父侧拿它跟发出时比：对不上就作废（`回执作废：执行时是第 2 代，发出时是第 1 代`），免得旧代次的动作结果被当成新代次的事实。

## 测试用的假服务端

`tests/fake-server.ts` 起一台刚够 mineflayer 进入世界的服务端：只发 `login`、`position`、`update_health`（外加可选的 `spawn_entity`）。mineflayer 收到第一条血量大于零的 `update_health` 才 emit `spawn`，所以这三件就够了。世界内容不在它的职责里。

`onAttack: "hurt"` 只广播一次受伤（`entity_status` 2 → mineflayer 的 `entityHurt`），`"kill"` 让实体消失，`"drop"` 掐掉连接——分别验"打中即完成"、目标消失、换代作废。

**假服务端推不动物理**（没有区块，服务端也不发位置更新），所以位移与方块类原语在它下面验不了判据；能真验的是"服务端能驱动的世界事实"。原语的控制循环由 `tests/fake-bot.ts` 的替身 + 假时钟覆盖。

## 还没有的

- **方块感知**：假服务端不发区块，采样面目前不读方块，弧还看不到"脚下是什么、前面是不是墙"。`dig` 的判据在真服务器上成立，在假服务端下没法构造。
- **动作库**：现在只有原语，`order` 的调用方（谁能把判决翻译成原语）还没落地，见 `docs/05-decisions.md` 的 U-03。
